# UCM Deployer 用户手册

**UCM (Unified Cache Management) 安装与环境预检工具 —— Windows 桌面版**

面向 vLLM / vLLM-Ascend / SGLang 运行环境（Ascend NPU / NVIDIA GPU），把 UCM 安装与环境预检简化为四个向导步骤：

```
① 服务器管理 → ② 镜像准备 → ③ 容器准备 → ④ 环境预检
```

- **步骤1 服务器管理**：SSH 登录信息本地加密保存/复用；单选登录一台服务器；`npu-smi`/`nvidia-smi` 设备探测（型号/卡数/CPU 架构）
- **步骤2 镜像准备**：复用已含 UCM 的镜像；支持上传 tar 包或输入镜像仓库地址自动拉取导入；确需构建时上传 wrapt/UCM/ucm-toolkit whl 并校验匹配
- **步骤3 容器准备**：选 UCM 镜像（自动校验）；自动探测并映射实际存在的 Ascend 设备节点、驱动与工具挂载，兼容 Ascend950PR/A5；KV Cache / 模型 / 自定义挂载；固定 `/bin/bash` 入口只创建容器、不启动推理服务；docker run 命令可编辑后执行；已有 UCM 容器可跳过创建
- **步骤4 环境预检**：显式选择目标容器并在其中运行 ucm-toolkit 预检（环境检查 + 可选挂载目录带宽测试）；UCM 与驱动版本识别失败时自动用 pip、version.info、npu-smi/nvidia-smi 多来源补齐，结果表格逐项展示

所有生成的命令与脚本都是**先展示、可编辑、再执行**。本工具负责 UCM 安装与环境预检，不负责启动或部署推理服务。

## 1. 安装与启动

### 直接使用 exe

双击 `UCM-Deployer.exe` 即可（无需 Python）。产物自检：

```powershell
.\UCM-Deployer.exe --smoke
```

### 源码运行 / 开发

```powershell
python -m venv .venv                       # Python 3.9+
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest             # 全部自检测试
.venv\Scripts\python main.py               # GUI
.venv\Scripts\python main.py --smoke       # 无头 GUI 冒烟
```

### 打包 exe

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
# 先跑全部测试，再产出 dist\UCM-Deployer.exe
```

推送 `v*` 标签触发 GitHub Actions 云端构建并发布 Release。

## 2. 环境要求

- 目标服务器：Linux + SSH + Docker
  - Ascend NPU 服务器需有 `npu-smi`
  - NVIDIA GPU 服务器需有 `nvidia-smi`
- 本地安装包（步骤2 需要）：
  - **UCM whl**：[GitHub Releases](https://github.com/ModelEngine-Group/unified-cache-management/releases)（uc_manager-*.whl）
  - **wrapt whl**：[PyPI wrapt 1.17.2 文件列表](https://pypi.org/project/wrapt/1.17.2/#files)（选择匹配服务器 Python 版本与 CPU 架构的 whl，如 manylinux 的 x86_64 / aarch64）
  - ucm-toolkit whl 包（可选）：与 UCM 包同站点 [GitHub Releases](https://github.com/ModelEngine-Group/unified-cache-management/releases) 下载，pip install 安装
- 使用「镜像仓库（服务器拉取）」时：目标服务器需能访问镜像仓库；工具会按已探测 CPU 架构选择 `linux/arm64` 或 `linux/amd64`。本地无需 Docker Desktop，也不会生成或上传 tar.gz

## 3. 五步操作详解

### 步骤1：服务器管理

1. **添加服务器**：名称、主机 IP、SSH 端口（默认 22）、用户名、密码或私钥认证；登录信息保存在 `~/.ucm_deployer/servers.json`（密码加密），下次打开可直接复用；
2. **测试连接**：验证 SSH 可达；
3. **探测设备**：自动识别 NPU/GPU 型号、卡数与 CPU 架构（uname -m）；探测结果会持久保存，作为步骤2/3 的适配依据；
4. 勾选「登录」选择本次要操作的服务器（**一次一台**，换勾自动切换）。

> 设备探测成功后，步骤2 的构建平台（ENV PLATFORM）与步骤3 的设备映射都会按该设备类型自动适配。

### 步骤2：镜像准备

1. **选择镜像来源**：默认使用「服务器已有镜像」，只需从列表选择基础镜像，无需填写仓库地址；服务器无法访问仓库时可切到「本地镜像包（离线导入）」上传 tar/tar.gz；服务器可访问仓库时可切到「镜像仓库（服务器拉取）」；
2. **镜像仓库拉取**：输入如 `quay.io/ascend/vllm-ascend:v0.30.0rc2-a5-openeuler`；工具生成可编辑的服务器命令（必须以 `docker pull` 开头），点「在服务器上拉取」后通过 SSH 执行；本地无需 Docker Desktop，也不会生成或上传 tar.gz；
3. **优先复用**：点「✅ 检查所选镜像 UCM」；若已安装 UCM，工具记录该镜像，可直接进入步骤3，**无需填写安装包或构建**；
4. **按需构建**（仅在基础镜像未安装 UCM 时；三个输入框下方均附**在线下载链接**）：
   - 选择基础镜像后自动探测运行时：Python 版本/ABI、CPU 架构、glibc、CANN/CUDA 与 Ascend 变体，并给出建议文件名
   - wrapt whl 包（必填）：选择后即时显示包名、Python ABI、架构、glibc 要求与匹配结果
   - UCM whl 包（必填）：额外校验 CANN/CUDA runtime 与 A2/A3/A5 设备变体
   - ucm-toolkit whl 包（可选）：与 UCM 包同站点（GitHub Releases）下载，pip install 安装
5. **新镜像名**：默认自动生成（`<基础镜像名>:ucm-<UCM版本号>`，如 `vllm-ascend:v0.23.0-a3` + UCM `0.8.0` → `vllm-ascend:ucm-0.8.0`；版本号取自所选 UCM whl 文件名，未选择时为 `:ucm`），可修改；手动修改后不再自动覆盖；
6. **校验匹配**：点「🔍 校验匹配」可手动触发；点击「🔨 开始构建」时也会**自动强制校验**，不通过则拒绝构建并说明原因：
   - 服务器设备类型（NPU/GPU）vs 镜像平台（按镜像名推断）
   - 基础镜像运行时（Python ABI、CPU 架构、glibc、CANN/CUDA）vs whl 文件名标记
   - UCM whl 的 CANN/CUDA runtime 与 A2/A3/A5 设备变体
7. **构建**：上传三个包 → 自动生成 Dockerfile（先离线安装 wrapt，再离线安装 UCM 与 ucm-toolkit whl）→ `docker build` → 校验新镜像内 UCM 已安装。

### 步骤3：容器准备

1. **选择 UCM 镜像**：进入本页自动加载服务器镜像列表；**选择镜像时自动后台校验镜像内 UCM 安装情况**（✓ 已安装版本 / ✗ 未安装提示回步骤2）；
2. **容器参数**：容器名（默认 `ucm-vllm`）、shm-size（默认 `512g`）、网络（Ascend 容器用 `--net=host`；NVIDIA 容器固定用 `-p` 端口映射）；
3. **KV Cache 挂载目录**：可添加多个（路径输入框支持「浏览」远端目录）；目录挂载到容器内相同路径；可点「🔍 文件系统校验」检查目录所在文件系统（本地/网络存储）；
4. **模型路径**：宿主机路径（支持远端浏览）→ 容器内路径（默认 `/models`），默认只读；
5. **自定义挂载**：任意宿主机/容器路径映射，可勾选只读；
6. **docker run 命令**：点「🔁 生成/刷新命令」自动生成——按服务器实际资源映射加速卡：
   - NPU：逐个探测实际存在的 `/dev/davinci*`、`davinci_manager`、`hisi_hdc`、`devmm_svm`、`ummu`、`uburma`，并只映射存在的节点；同时筛选实际存在的 Ascend 驱动/工具/配置挂载；A5/950PR 检测到 `ummu`/`uburma` 时自动添加 `--privileged=true`
   - GPU：`--runtime nvidia --gpus all -p 8000:8000 --ipc=host`
   - 固定生成 `--entrypoint /bin/bash`，不在镜像后追加 `bash`，只创建并保持 Bash 容器运行，不启动 vLLM；
   - 命令**可编辑**，点「🚀 创建容器」按编辑框内容执行；执行前校验入口仍是 `/bin/bash`；
7. 点「✅ 检查容器内 UCM」确认容器可用。

> 若服务器上已有安装 UCM 的容器，可跳过本页创建操作，直接进入步骤4刷新并选择该容器。

### 步骤4：环境预检

在**显式选择的目标容器内**运行 `ucm-toolkit run precheck`，提前发现可能影响启动或缓存读写的问题：

1. **目标容器**：点「🔄 刷新容器」读取服务器 `docker ps -a`，在下拉框中选择已有容器；也可手动输入容器名。页面状态行会显示当前目标容器，预检命令始终作用于该容器；
2. **执行存储带宽检查（默认开启）**：
   - 开启：填写**容器内**挂载目录（须为步骤3 已映射进容器的目录；「浏览」列出的是**容器内可见目录**，未创建容器时引导返回步骤3）——预检会在该目录下**创建临时子目录**（`ucm-precheck-*`）执行读写负载，**运行日志会播报该临时目录的完整路径**（含清理结果），便于在环境上核对目录是否存在/已被清除；结束后自动清理，不污染用户数据；目录容器内不存在时会**预检前拦截报错**（不会凭空创建）；请确保目录有可用空间；
   - 关闭：仅环境检查（`--skip-bandwidth`，驱动/内核/共享内存/AIO），**无需填写挂载目录**（输入框自动禁用）；
3. **预检参数配置**（「⚙ 预检参数配置...」）：
   - 预检参数依赖随 ucm-toolkit 安装的 JSON 配置文件（`<site-packages>/ucm_toolkit/tools/precheck/precheck.defaults.json`，含带宽矩阵、各项阈值）；
   - 点击后自动从容器读取当前配置（优先已保存的自定义配置，否则出厂默认）到编辑框，**实时校验 JSON 语法**；
   - 「保存并启用」写入容器内 `/root/ucm-deploy/precheck.json`，此后预检以 `--config` 引用——**叠加于出厂默认之上，只需写要覆盖的键**（如 `{"bandwidth": {"threshold_gb": 4.0}}` 只改带宽阈值）；
   - 「恢复默认配置」删除容器内自定义文件，回到出厂默认；
   - 页面「预检参数：」状态实时显示当前使用出厂默认/自定义配置（进入页面时自动探测，容器重建后自动复位）；
4. 点「🔍 开始预检」：过程输出实时进入底部日志页签；
5. **结果展示**：表格逐项列出（状态列着色：PASS 绿 / WARN 橙 / FAIL 红 / INFO·SKIP 灰），摘要列单行；**点击结果行，右侧详情区显示完整详情与中文排查建议**；顶部汇总行显示判定与统计（如 `PASSED (with warnings) | 2 pass, 2 warn, 0 fail`）。

> 提示：容器内 `npu-smi info` 若报 `rc=172` / `ret is -8020 (device is used)`，通常表示 NPU 正被其他进程/容器占用（宿主机上 `npu-smi info` 可正常查看），该 WARN 不影响带宽检查结果。

### 步骤5：批量部署（多服务器）

在**一台服务器上制作好镜像**（步骤1-2）后，向**多台目标服务器**批量执行「镜像分发 → 容器创建 → 环境预检」，并在同一面板内查看**每台服务器各自的执行进展**：

1. **镜像来源**：
   - **镜像包中转**（默认）：源服务器上 `docker save | gzip -1` 导出镜像包 → 下载到本机 → 各目标并行上传并 `docker load`。离线集群（目标无法访问镜像仓库）适用；源服务器自动作为面板首行先准备镜像包，其余目标就绪后并行分发；
   - **镜像仓库**：各目标服务器直接 `docker pull`（填写仓库镜像地址，如 `quay.io/ascend/vllm-ascend:v0.30.0rc2-a5-openeuler`），无需源服务器；
   - 勾选「目标已存在同名镜像时跳过分发」：逐台 `docker image inspect` 检查，已存在则跳过上传/拉取，直接进入容器创建（重复执行/增量补装场景）；
   - 进入本页时自动带入步骤2 构建完成的镜像与源服务器；
2. **目标服务器**：从注册表勾选**多台**（「全选/清空/刷新」辅助）；源服务器也可以同时作为目标（其镜像分发阶段自动跳过，容器创建/预检照常执行）；
3. **部署配置模板**（对全部目标生效，设备差异自动适配）：
   - **容器配置**：容器名 / shm-size / --net / 端口映射（NVIDIA）/ KV Cache 目录（多行）/ 模型挂载（只读可选）/ 额外挂载（多行）/ 附加 docker 参数。Ascend 目标会**逐台现场探测**实际存在的设备节点（`/dev/davinci*`、`/dev/ummu` 等，存在时自动 `--privileged`）与驱动/工具挂载；NVIDIA 目标自动使用 `--runtime nvidia --gpus all`；
   - **预检配置**：是否执行带宽检查、容器内挂载目录、可选自定义预检 JSON 配置（会写入**每个目标容器**内 `/root/ucm-deploy/precheck.json` 并以 `--config` 引用；出厂默认可在步骤4「预检参数配置」中读取参考）；
   - 创建容器前自动校验镜像内 UCM 安装（未安装则该服务器失败并说明原因）；
4. **执行**：勾选要执行的阶段（镜像分发 / 容器创建 / 环境预检，可任意组合）；「同名容器先删除再创建」适用于重复执行场景；点「🚀 开始批量部署」后，面板**每台服务器一行进度条 + 一页独立日志**，逐台显示各阶段进展与命令输出；结束后弹出汇总（每台：镜像分发/跳过、容器名、预检判定）；
5. **数据模板（JSON）导入/导出**：多台服务器的登录信息、容器创建参数、预检参数往往重复填写——把它们保存为**部署数据模板**：
   - 「📤 导出部署模板」：当前勾选的目标服务器登录信息 + 镜像来源 + 容器/预检配置导出为 JSON（登录密码/私钥口令默认**不**导出，确认后可包含，注意明文风险）；
   - 「📥 导入部署模板」：一次填充全部配置；模板中的服务器按 `主机+端口+用户名` 匹配写入本机注册表（已存在则更新且模板密码为空时保留本地密码），并自动勾选为目标；
   - 模板是纯 JSON，可直接手工编辑/批量生成后分发给同事，在其机器上导入即用。

模板文件格式示例（字段均可选，详见实际导出文件）：

```json
{
  "kind": "ucm-deployer-batch-template",
  "template_version": 1,
  "image": {
    "mode": "tar",
    "ref": "ucm-vllm:0.3.6",
    "source_host": "10.0.0.10",
    "source_port": 22,
    "skip_existing": true,
    "recreate_container": false
  },
  "container": {
    "name": "ucm-vllm", "shm_size": "512g", "network": "host",
    "ports": ["8000:8000"], "kv_cache_dirs": ["/mnt/kvcache"],
    "model_mount": {"host_path": "/data/models", "container_path": "/models", "readonly": true},
    "extra_mounts": [], "extra_args": ""
  },
  "precheck": {
    "bandwidth_check": true, "mount_path": "/mnt/kvcache",
    "custom_config_enabled": false, "custom_config_json": {}
  },
  "servers": [
    {"name": "node-1", "host": "10.0.0.11", "port": 22, "username": "root",
     "auth_type": "password", "password": "", "remark": ""}
  ]
}
```

> 提示：批量执行期间日志按服务器分页，单台失败不影响其他服务器继续执行；汇总后可针对失败的服务器查看其日志页排查（常见：SSH 不通、磁盘空间不足、镜像无 UCM、挂载目录不存在）。

## 4. 工具菜单：清理容器 / 清理镜像

安装与预检流程之外的两个运维善后工具（作用于当前勾选登录的服务器）：

1. 菜单「工具 → 清理容器...」：自动加载服务器上全部容器（**含已停止**，`docker ps -a`）；勾选后点「删除选中」，确认后执行 `docker rm -f`（**运行中的容器将被强制停止并删除**）；完成后列表自动刷新；
2. 菜单「工具 → 清理镜像...」：自动加载服务器上全部镜像；勾选后点「删除选中」，确认后执行 `docker rmi -f`（**被运行中容器引用的镜像会被强制删除**）；完成后列表自动刷新；
3. 两个对话框均支持**关键字筛选**（整行匹配名称/ID/状态等，不区分大小写；筛选不丢失已勾选），长镜像名/容器名**悬浮可见完整名称**，列表超宽可横向滚动；
4. 两处均有「刷新列表」按钮；删除前弹确认框列出全部将删除的对象名。

## 6. FAQ

**Q: 密码安全吗？**
密码使用 Fernet 对称加密保存在本地（`~/.ucm_deployer/servers.json` 密文 + `.secret.key` 密钥）。密钥与密文同目录，防止 servers.json 被单独拷贝后直接泄露明文；属内网运维工具的折中方案。

**Q: 镜像构建失败：pip install 报 wrapt 找不到？**
请确认选择的 wrapt whl 与服务器架构匹配（manylinux x86_64/aarch64）；输入框下方的即时反馈与「校验匹配」都会提示架构标记。

**Q: 步骤3 提示「镜像未安装 UCM」？**
选择镜像时会自动校验；若未安装请回步骤2 构建，或选择其他已装 UCM 的镜像。

**Q: 「匹配校验不通过：镜像疑似 ascend/nvidia 平台...」？**
按镜像名推断的平台与服务器设备不一致。请更换与服务器设备匹配的基础镜像；若镜像名不含平台关键字（如自定义镜像名），会降级为警告而非错误。

**Q: 日志在哪里？**
`~/.ucm_deployer/logs/ucm_deployer.log`（菜单「帮助 → 打开日志目录」）。

**Q: 如何在无真实服务器时验证程序？**
