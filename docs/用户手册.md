## 1. 简介

UCM Deployer 把 UCM 部署到多台 GPU/NPU 服务器的推理容器集群中，覆盖完整流程：

| 步骤 | 功能 |
|---|---|
| 1. 服务器管理 | SSH 登录信息加密保存/复用，选择部署服务器，设备型号一致性校验 |
| 2. 镜像构建 | 基础镜像（或上传 tar 包 docker load）+ UCM whl（离线含 wrapt）→ 带 UCM 的引擎镜像 |
| 3. 容器创建 | 自动识别卡数生成 docker run（kvcache 挂载/模型只读映射/设备映射），命令可编辑 |
| 4. 部署配置 | PD 混部/PD 分离拓扑与卡数校验、资源占用检查、自动生成含 UCM kv-transfer-config 的启动脚本 |
| 5. 拉起服务 | 脚本部署、按依赖顺序拉起（mooncake/ray/引擎/负载均衡）、健康检查、日志跟踪 |

所有生成的命令与脚本**先展示、可编辑、再执行**。

## 2. 安装与启动

### 2.1 直接使用 exe

拿到 `UCM-Deployer.exe` 后双击运行即可（无需安装 Python）。

自检（可选）：

```powershell
.\UCM-Deployer.exe --selftest --out report.txt   # 内置模拟服务器跑全流程
type report.txt
```

### 2.2 源码运行

```powershell
git clone <本仓库>
cd UCM-Deployer
python -m venv .venv                      # 需 Python 3.9+
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python main.py
```

### 2.3 自己打包 exe

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
# 产物: dist\UCM-Deployer.exe （脚本会先跑全部测试再打包）
```

云端方式（推荐）：推送 `v*` 标签后 GitHub Actions 自动「测试 → 打包 → 自检 → 发布到 Release」，
本页的 exe 即由此产出，无需本地构建上传。

## 3. 快速体验：模拟服务器

本工具内置一台「模拟 Ascend/NVIDIA + Docker 服务器」，无需真实环境即可体验/验证完整流程：

```powershell
.venv\Scripts\python -m ucm_deployer.mock.mock_server --port 2222 --device ascend --cards 8
# NVIDIA: --device nvidia --cards 4
# 预置已含UCM的镜像（跳过构建步骤）: --preload-ucm-image
```

然后打开 UCM Deployer：

1. 步骤1 → 「添加服务器」→ 主机 `127.0.0.1`、端口 `2222`、用户 `root`、密码 `root`；
2. 勾选该服务器 → 「探测设备并校验一致性」→ 应显示 `Ascend 910B3 x8`；
3. 之后各步骤与真实服务器完全一致（构建镜像时选择任意 UCM whl 文件即可，模拟服务器会解析 Dockerfile 完成构建）。

## 4. 步骤1：服务器管理

### 界面操作

- **添加服务器**：填写名称/IP/端口/用户名，认证方式支持密码或私钥（私钥可选口令）；
- **编辑 / 删除**：选中一行后操作；
- **测试连接**：对勾选的服务器批量发起 SSH 连接测试；
- **探测设备并校验一致性**：对勾选的服务器执行 `npu-smi info` / `nvidia-smi`，识别型号与卡数，并校验**所有服务器设备型号一致**（卡数不同仅提示警告，请按实际卡数规划拓扑）；
- 勾选「部署」列即选择**本次要部署的服务器**（可以是保存列表的子集）。

### 登录信息保存位置

`~/.ucm_deployer/servers.json`（密码经 Fernet 加密，密钥在同目录 `.secret.key`），下次打开程序可直接复用。

## 5. 步骤2：镜像构建

> 若服务器上已有安装了 UCM 的镜像：选择镜像 → 「检查所选镜像 UCM」确认已安装 → 「使用已有 UCM 镜像，跳过构建」直接进步骤3。

### 操作流程

1. **镜像列表自动加载**：进入本页即拉取每台服务器的 `docker images`；镜像**只能从下拉列表选择**（不可手输），显示镜像名/Tag/大小，悬浮显示创建时间，含 UCM 的镜像排在最前；服务器镜像有变化时可点「刷新镜像列表」；
2. 服务器上没有可用基础镜像时：**上传镜像 tar/tar.gz 并 docker load**（选择本地 tar 包，自动上传并加载后出现在下拉框）；
3. 为每台服务器选择**基础镜像**（vllm-ascend / vllm / sglang 官方镜像等）；
4. 选择本地 **UCM whl 包**（必填）。本地没有时在线获取：
   - UCM whl：[GitHub Releases](https://github.com/ModelEngine-Group/unified-cache-management/releases)（uc_manager-*.whl）
   - wrapt whl：[PyPI 文件列表](https://pypi.org/project/wrapt/#files)（选择匹配服务器 Python 版本与 CPU 架构的 whl，如 manylinux 的 x86_64 / aarch64）

   界面上对应输入框下方有可直接点击的下载链接；
5. 选择联网模式：
   - **联网**：`pip install` 时自动从 pypi 拉取 wrapt 等依赖；
   - **离线**：需额外提供本地 **wrapt whl**（先装 wrapt 再以 `--no-index` 安装 UCM）；
6. 可选：**ucm-toolkit 源码目录**（自动打 tar 上传并在镜像内源码安装）；
7. 新镜像名默认按基础镜像自动生成（如 `vllm-ascend:v0.23.0-a3` → `vllm-ascend-ucm:v0.23.0-a3`），可修改；
8. **开始构建**：每台服务器并行执行，显示进度与日志。

### 构建过程（自动完成）

```
远端 /tmp/ucm-build-xxxx/
├── uc_manager-x.x.x-py3-none-any.whl   ← SFTP 上传
├── wrapt-x.x.x.whl                      ← 离线模式上传
└── Dockerfile                           ← 自动生成
    FROM <基础镜像>
    ENV PLATFORM=ascend|cuda
    RUN pip install [--no-index --find-links=...] /tmp/ucm-pkgs/wrapt...whl
    RUN pip install [--no-index --find-links=...] /tmp/ucm-pkgs/uc_manager...whl
```

构建完成后自动 `docker run --rm --entrypoint /bin/sh <新镜像> -c 'pip show uc-manager'` 校验 UCM 安装。

## 6. 步骤3：容器创建

> 本页配置区支持**滚轮滑动**（窗口较小时可上下滚动查看全部配置；任务进度/日志面板固定在底部始终可见）。

### 界面操作

1. **检查镜像内 UCM**：对所选镜像执行 pip show，未安装会提示回到步骤2；
2. 填写**容器名**（默认 `ucm-vllm`）、shm-size（默认 512g）、网络（默认 host）；
3. **kvcache 持久化挂载目录**：
   - 「浏览...」可打开远端目录浏览器（下拉选择）；
   - 可添加多个目录，但**必须在同一共享文件系统**上；
   - 「共享文件系统校验」会通过 `df --output=source,fstype` 校验：同一服务器目录同源、跨服务器存储源一致且为 NFS/3FS 等网络文件系统；
   - ⚠ **只有「同一种模型 + 同一种部署形态（P 节点数、DP/TP 一致）」的服务才能共用同一套挂载目录/文件系统**；
4. **模型路径**：宿主机目录 → 容器内路径（默认 `/models`，默认只读 ro）；
5. **其他挂载**：表格方式添加（宿主机路径 / 容器内路径 / 只读）；
6. **生成/刷新命令**：按设备类型自动生成全量 `docker run` 命令（**每台服务器一个命令页签**，可分别编辑，创建时按各页内容执行）：
   - Ascend：`--device /dev/davinci0..N-1`（按探测卡数全量映射）+ `davinci_manager/devmm_svm/hisi_hdc` + 驱动目录挂载；
   - NVIDIA：`--gpus all` + `--ipc=host`；
7. **创建容器**：全部服务器并行执行；之后可「检查容器内 UCM」。

> 提示：鼠标悬停在各输入框上可查看参数说明；「浏览...」打开的远端目录浏览器支持多服务器切换。

## 7. 步骤4：部署配置

### 操作流程

1. 「刷新容器列表」→ 每台服务器选择**已安装 UCM 的容器** → 「检查容器内 UCM」；
2. 「卡资源占用检查」：检查运行中的容器、vllm/sglang/ray/mooncake 进程、GPU 计算进程（NVIDIA），被占用时会提示；
3. 选择**部署形态**：
   - **PD 混部**：所有服务器不区分角色；
   - **PD 分离**：每台服务器指定 P(Prefill) 或 D(Decode)，并配置各自 DP/TP；
   - 「自动填满卡数」：DP = 卡数 / TP；
4. 选择**引擎**：vLLM 或 SGLang（SGLang 当前仅支持单机混部自动生成）；
5. 填写服务参数：模型路径（容器内）、`--served-model-name`、UCM 配置文件路径、kvcache 共享目录、通信网卡（留空自动探测）、端口规划（服务起始端口/mooncake 起始端口/PP）、**附加参数**（每行一个，如 `--max-model-len 32000`）；
6. 底部**实时校验**：红色错误必须解决（如 DP×TP 超卡数、PD 缺 P/D 节点、组内 TP 不一致），黄色为提示；
7. **生成部署脚本**：右侧出现全部脚本（可编辑），进入步骤5时生效。

### 卡数校验规则

- 每节点：`DP × TP ≤ 可用卡数`；
- 多机混部（ray）：`TP × PP` 需能均分到各服务器且不超过总卡数，暂不支持 DP>1（请用 PD 分离）；
- PD 分离：P 组与 D 组各自要求 ≥1 节点、组内 TP 一致；P/D 两组 TP 不一致时给出提示。

## 8. 步骤5：拉起服务

1. **部署脚本到容器**：把脚本与配置 `docker cp` 到各容器 `/root/ucm-deploy/`；
2. **全部拉起（按依赖顺序）**：mooncake master → ray head/worker → prefill/decode/serve → 负载均衡；任一脚本拉起失败会**立即停止后续拉起**并提示（排查后可单独重试）；也可对单个脚本点「拉起」；
3. **健康检查**：对每个服务端口执行 `curl /health`（引擎启动需数分钟，可多次重试；结果汇总见弹窗）；
4. **日志**：点每行「日志」查看容器内日志尾部（支持自动刷新 5s）；
5. **停止**：单脚本停止或全部停止（pkill 对应进程）。

> 主窗口底部**状态栏**实时显示：已选服务器数 / UCM 镜像 / 容器 / 脚本生成状态 / 后台任务数。
> 菜单「帮助」提供：用户手册（**程序内直接显示**）、打开日志目录、打开配置目录、自检（模拟服务器全流程）。
> 左侧导航有流程门控：前置步骤未完成时会提示并停留在当前步骤。退出时若有后台任务运行会请求确认。

## 10. 生成的脚本说明

脚本落在容器内 `/root/ucm-deploy/`，日志在 `/root/ucm-deploy/logs/`。生成模板与 UCM 官方文档一一对应：

| 场景 | 脚本 | 对应文档 |
|---|---|---|
| 混部（单机） | `serve.sh`：UCMConnector `kv_both` | Quickstart-vLLM-Ascend |
| 混部（单机 DP>1） | `serve_dp.sh`：按 DP 循环拉起进程（卡段/端口/外部LB DP 参数） | vLLM Data-Parallel external LB |
| 混部（多机） | `ray_head.sh` / `ray_worker_N.sh` / `serve.sh`（head 上 TP×PP 跨机） | vLLM-Ascend 多机混部教程 |
| PD 分离 | `mooncake_master.sh`、`mooncake.json`、`prefill.sh`（MultiConnector = MooncakeConnectorV1 kv_producer + UCMConnector kv_both）、`decode.sh`（kv_consumer）、`load_balancer.sh` | Distributed PD Disaggregation on Ascend |
| SGLang 混部 | `serve.sh`：`--enable-hierarchical-cache` + `ucm.integration.sglang.unifiedcache_store` | Quickstart-SGLang |
| UCM 配置 | `ucm_config.yaml`（UcmPipelineStore 模板，storage_backends 指向共享目录） | examples/ucm_config_example.yaml |

要点：

- mooncake 端口按官方文档步进：`起始端口 + dp_rank × TP`；
- `ENABLE_UCM_PATCH=1`（vLLM ≥ 0.11 的 monkey patch）默认开启，可在步骤4关闭；
- Ascend 环境变量（`HCCL_IF_IP`、`GLOO/TP/HCCL_SOCKET_IFNAME`、`ASCEND_RT_VISIBLE_DEVICES` 等）自动注入，网卡未指定时脚本内自动探测；
- **所有脚本均可在步骤4生成后直接编辑**。

## 11. 常见问题

**Q: 连接服务器失败？**
检查 IP/端口/密码；服务器需开启 SSH（22 或自定义端口）；私钥认证请确认 key 文件路径。错误详情见页面下方日志。

**Q: 「docker 不可用」？**
目标服务器需安装并启动 docker；当前用户需有 docker 权限（root 或 docker 组）。

**Q: 镜像构建失败：pip install 报 wrapt 找不到？**
离线模式请提供与服务器架构匹配的 wrapt whl（manylinux x86_64/aarch64）；联网模式确认服务器可访问 pypi。

**Q: 共享文件系统校验不通过？**
多个 kvcache 目录必须同一文件系统；多服务器部署时必须是 NFS/3FS 等网络存储（程序会区分本地盘与网络盘）。单机使用本地盘可继续（有提示）。

**Q: 健康检查一直失败？**
引擎启动需 1-10 分钟；点「日志」查看启动进度。PD 模式需 mooncake master 先就绪。若日志有端口冲突，检查端口规划。

**Q: 修改了服务器登录信息后步骤2-5数据还在吗？**
在步骤1改变勾选后，未勾选服务器的镜像/容器选择会自动清理。

**Q: exe 双击无反应？**
可用 `UCM-Deployer.exe --selftest --out report.txt` 自检并查看报告；日志文件在 `~/.ucm_deployer/logs/`。

## 12. 安全说明

- SSH 密码/私钥口令保存在本机 `~/.ucm_deployer/servers.json`，使用本机密钥（`.secret.key`）Fernet 加密，拷贝 servers.json 到其他机器无法解密；
- 程序只通过 SSH 操作服务器，不在服务器上驻留任何组件；
- 生成的容器默认 `--net=host`，请确保端口规划不与服务器现有服务冲突。
